# 大阪大学 軽音楽部 SWING 公式サイト

大阪大学軽音楽部SWINGの公式ウェブサイトのソースコードです。

---

## はじめに読んでください

このページは、サイトを**編集・更新したい部員向け**の説明書です。  
プログラミングをやったことがなくても、手順通りに進めれば動かせるように書いています。  
わからないことがあれば、管理者（サイト担当の部員）に聞いてください。

---

## サイトを自分のパソコンで動かすまでの手順

### ステップ 1：必要なソフトをインストールする

2つのソフトが必要です。すでに入っている場合はスキップしてください。

**① Node.js**（サイトを動かすエンジンです）  
→ https://nodejs.org/ja/ にアクセスして「推奨版」をダウンロード・インストール

**② Git**（ファイルの履歴管理ツールです）  
→ https://git-scm.com/ にアクセスしてダウンロード・インストール

---

### ステップ 2：このプロジェクトをダウンロードする

ターミナル（Macなら「ターミナル」、Windowsなら「コマンドプロンプト」）を開いて、以下を入力してください。

```
git clone https://github.com/SapphMizi/swing-hp.git
cd swing-hp
```

> **ターミナルって何？**  
> 文字を打ってパソコンに命令するツールです。Macはスポットライト検索で「ターミナル」と検索すると出てきます。

---

### ステップ 3：必要なファイルを準備する

以下のコマンドを入力してください（時間がかかる場合があります）。

```
npm install
```

> これは「このサイトに必要な部品を全部ダウンロードする」という命令です。

---

### ステップ 4：サイトを起動する

```
npm run dev
```

このコマンドを実行したあと、ブラウザで **http://localhost:3000** を開くとサイトが表示されます。

> `localhost` とは「自分のパソコンの中だけで動いているサイト」のことです。インターネットには公開されていないので安心して触れます。

## 記事の投稿と写真の差し替え（広報担当向け）

お知らせ、ライブレポート、トップの写真、バンド紹介、歴史、連絡先は、microCMS（ブラウザで使う管理画面）で更新します。コードを触る必要はありません。microCMS で「公開」してから1分ほどで、サイトに反映されます。

管理画面のアドレスとログイン用のメールアドレス・パスワードは、前の広報担当から引き継いでください。

### お知らせを書く

1. microCMS にログインし、左の一覧から「posts」を開く
2. 右上の「追加」を押す
3. 「種類」で「お知らせ」を選ぶ
4. 「タイトル」「日付」「本文」を書く。写真は任意
5. 右上の「公開」を押す

トップには新しい順に3件が表示されます。4件以上あると「もっと見る」が出て、お知らせの一覧ページに進めます。

### ライブレポートを書く

お知らせと同じ「posts」に書きます。違うのは次の3点です。

- 「種類」で「ライブレポート」を選ぶ
- 「日付」にはライブの日を入れる。ライブレポートの一覧は、この日付の年でタブに分かれる
- 「出演したバンド」を選ぶ。記事のページにバンド名が表示される

「写真」を入れると、一覧に紙に貼った写真のように並びます。写真がないときは、タイトルを書いた色の面になります。

### トップの写真を差し替える

1. 左の一覧から「site」を開く
2. 「トップの写真」の写真を消す・追加する。最大5枚で、上にある写真が最初に表示され、6秒ごとに切り替わる
3. 「公開」を押す

横長（4:3 くらい）の写真がきれいに収まります。写真を1枚も入れないと、トップには手描きのロゴだけが大きく表示されます。

### メールアドレスや SNS の URL を変える

- 部のメールアドレス、部の Instagram と X の URL は「site」で変える
- 各バンドの紹介文、写真、Instagram と X の URL は「bands」で変える。空欄のバンドには「準備中です」と表示される

### 歴史の年表に行を加える

「history」に「年」と「出来事」を追加します。同じ年の出来事は、サイトでは1行にまとめて表示されます。history が空のあいだは、コードに入っている1961年から1973年までの年表が表示されます。

### 英語の欄について

「（英語・任意）」と書いてある欄は、書かなくてもかまいません。空のときは、英語表示でも日本語の文が出ます。

### 広報担当が交代するとき

無料プランではメンバーを3人までしか登録できないので、広報担当用のアカウントを1つ共有しています。交代するときは、次の担当にログイン情報を渡し、パスワードを変更してください。

## microCMS の準備（最初に1回だけ。サイト担当向け）

1. https://microcms.io/ でアカウントを作り、サービスを1つ作る（Hobby プラン、無料）
2. API を4つ作る。どれも「API スキーマをインポート」で `docs/microcms-schema/` の JSON を読み込む

   | エンドポイント | 型 | インポートするファイル |
   |---|---|---|
   | `posts` | リスト形式 | `api-posts.json` |
   | `site` | オブジェクト形式 | `api-site.json` |
   | `bands` | リスト形式 | `api-bands.json` |
   | `history` | リスト形式 | `api-history.json` |

   インポートできなかったときは、JSON に書いてあるフィールド ID、表示名、種類のとおりに手で作る。セレクトフィールドの選択肢の文言(「お知らせ」「ライブレポート」と3バンドの正式名)は、`src/server/cms.ts` と `src/lib/bands.ts` の文言と一字一句同じにする

3. 「bands」に3バンドを入力する。「並び順」は Blue Spirits Jazz Orchestra を 1、Swing Arcade Orchestra を 2、The New Wave Jazz Orchestra を 3 にする
4. 「API キー」の画面で、GET だけを許可したキーを確認する
5. 環境変数を2つ設定する。ローカルではリポジトリ直下に `.env.local` を作る。本番では Vercel のプロジェクトの Settings → Environment Variables に同じ2つを入れる

   ```
   MICROCMS_SERVICE_DOMAIN=サービスID（xxxx.microcms.io の xxxx の部分）
   MICROCMS_API_KEY=API キー
   ```

環境変数がない状態でもサイトは表示されます。そのときは、お知らせとライブレポートは「まだありません」、バンド紹介と歴史はコードに入っている内容になります。

## コードで変える内容（サイト担当向け）

| 変えたい内容 | 編集するファイル |
|---|---|
| ナビゲーションやボタンなどの日本語の文言 | `src/i18n/ja.ts` |
| 同じく英語の文言 | `src/i18n/en.ts` |
| 色やフォント | `src/styles.css`（決めた理由は `docs/requirements.md`） |
| 手描きの部品（ロゴ、吹き出し、キャラクター） | `public/images/hand/` |
| microCMS が空のときのバンド紹介と年表 | `src/lib/defaults.ts` |

デザインの方針は `docs/requirements.md` と `.claude/skills/swing-ui/SKILL.md` にまとめてあります。見た目を変えるときは先に読んでください。

## 変更をGitHubに保存する（公開・バックアップ）

このプロジェクトでは、**ブランチ → プルリクエスト** という流れで変更を取り込みます。  
直接 `main` ブランチに push するのは禁止です。必ず以下の手順に従ってください。

> **なぜこのルールがあるの？**  
> 直接 `main` に保存してしまうと、間違いがあってもすぐ本番サイトに反映されてしまいます。  
> 一度「草稿（ブランチ）」に保存 → 別の人にチェックしてもらう（プルリクエスト）という手順を踏むことで、ミスを防げます。

---

### ステップ 1：ブランチを作る

ブランチとは「作業用のコピー」のようなものです。`main` を直接触らずに、自分専用の作業スペースを作ります。

```
git checkout -b ブランチ名
```

ブランチ名は何をするか分かるように英語でつけます（日本語は使えません）。

```
例）
git checkout -b update-sns-links       ← SNSリンクを更新するとき
git checkout -b add-live-report-2025   ← ライブレポートを追加するとき
git checkout -b fix-schedule           ← スケジュールを修正するとき
```

---

### ステップ 2：ファイルを編集する

ブランチを作ったら、普通にファイルを編集してください。

---

### ステップ 3：変更を保存する（コミット）

編集が終わったら、変更内容をGitに記録します。

```
git add .
git commit -m "変更内容の説明（日本語でOK）"
```

コミットメッセージの例：
```
git commit -m "各バンドのSNSリンクを正式なURLに変更"
git commit -m "2025年6月定期ライブのレポートを追加"
```

---

### ステップ 4：GitHubにアップロードする（プッシュ）

```
git push origin ブランチ名
```

ステップ1でつけたブランチ名を入れてください。

```
例）
git push origin update-sns-links
```

---

### ステップ 5：プルリクエストを送る

1. **https://github.com/SapphMizi/swing-hp** をブラウザで開く
2. 黄色いバナーで「Compare & pull request」というボタンが出るのでクリック
3. タイトルと説明を書いて「Create pull request」をクリック

> **プルリクエストって何？**  
> 「この変更を本番に取り込んでいいですか？」という確認申請です。  
> 管理者がチェックして問題なければ「Merge（取り込む）」します。マージされると初めてサイトに反映されます。

---

### ステップ 6：マージ後に後片付けをする（任意）

プルリクエストがマージされたら、作業用ブランチを削除して `main` を最新状態に戻しておきましょう。

```
git checkout main
git pull
git branch -d ブランチ名
```

## ファイル構成（参考）

```
swing-hp/
├── public/images/hand/      ← アイコンから切り出した手描きの部品
├── src/
│   ├── routes/              ← 各ページ
│   ├── components/          ← ページの部品
│   ├── server/cms.ts        ← microCMS からデータを読む処理
│   ├── lib/                 ← 型、既定のデータ、バンドの名前と色
│   ├── i18n/                ← 日本語と英語の文言
│   └── styles.css           ← 色とフォント
├── docs/
│   ├── requirements.md      ← 要件定義書（デザインの方針）
│   └── microcms-schema/     ← microCMS にインポートするスキーマ
├── PRODUCT.md               ← サイトの利用者と目的
└── _reference/              ← 移行前の旧HTMLサンプル（参考用）
```

## 困ったときは

- **サイトが表示されない** → `npm install` をもう一度試してみてください
- **コマンドがエラーになる** → Node.js のバージョンが古い可能性があります。公式サイトから最新版をインストールしてください
- **それでも解決しない** → サイト担当の部員に連絡してください
