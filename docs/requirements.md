# swing-hp 要件定義書(デザイン刷新と microCMS 導入)

サイトの利用者、目的、制約は `PRODUCT.md` にまとめてある。この文書は、その前提の上で、見た目と更新の仕組みをどう作り直すかを決める。実装はこの文書の内容に従い、変えるときは先にこの文書を直す。

## 1. 背景

いまのサイトは、黒背景にアンバーの差し色、角丸のカードとぼかした光、スクロールでふわっと出るアニメーションでできている。この組み合わせは AI が生成するサイトによく見られ、部の SNS アイコン(桃色の紙に色鉛筆で描いた手描きの絵)とも雰囲気が合っていない。

また、記事やトップ画像を変えるにはコードを書き換える必要があり、広報担当の部員だけでは更新できない。

## 2. 配色

アイコン(`public/images/swing_logo.jpg`)から抜き出した色をもとに、次のトークンを `src/styles.css` の `@theme` に定義する。いまの `swing-*` のトークンはすべて置き換える。

| トークン | 値 | アイコンでの元の色 | 使い方 |
|---|---|---|---|
| `paper` | #fbdcc0 | 紙(#fdd7b5、#f6cba6) | ヒーローとセクションの背景 |
| `paper-light` | #fdeee1 | 紙を明るくした色 | 記事本文など長い文章の背景 |
| `ink` | #2b1d1f | 線の焦げ茶 | 本文、見出し、濃い帯の背景 |
| `pink` | #e0456f | 「N」のピンク(#f84c7c) | 塗り(付箋、下線、イラスト)。文字には使わない |
| `pink-deep` | #b0304f | `pink` を暗くした色 | リンクの文字、ボタンの背景 |
| `blue` | #3f6f96 | ギターの青(#4b7ba1) | 2番目の差し色の塗り。文字には使わない |
| `blue-deep` | #355f82 | `blue` を暗くした色 | 2番目の差し色の文字 |
| `teal` | #7abdc5 | サックスの水色 | 背景の面(文字は `ink`)、装飾 |
| `orange` | #f0904a | 「G」の橙 | 背景の面(文字は `ink`)、装飾 |
| `yellow` | #fbd96e | 吹き出しの黄 | 吹き出し、付箋、背景の面(文字は `ink`) |
| `green` | #8fb85a | 傘の黄緑 | 背景の面(文字は `ink`)、装飾 |
| `red` | #ea5a48 | 「N」の赤 | Swing Arcade Orchestra の面(文字は `ink`、4.66:1) |
| `navy` | #23365e | 鍵盤の黒鍵の紺 | The New Wave Jazz Orchestra の面(文字は `paper-light`、10.5:1) |

- リンクとボタンの色は `pink-deep` に統一する。青系は2番目の差し色として、文字やアイコンに使う
- `teal`、`orange`、`yellow`、`green` は、お知らせの行や付箋などの背景の面として広く塗ってよい。アイコンの色鉛筆の色が面で見えることで、紙色に差し色を少し置いただけの見た目を避ける。面の上の文字は `ink` にする(コントラスト比は `orange` 上の 6.77:1 が最小)
- 3つのバンドは、部が決めているテーマカラーに近い色をアイコンの中から選んで面に塗る。Blue Spirits Jazz Orchestra(青と白)は `blue` の面に `paper-light` の文字(4.71:1)、Swing Arcade Orchestra(赤と黒)は `red` の面に `ink` の文字、The New Wave Jazz Orchestra(紺と白)は `navy` の面に `paper-light` の文字。対応は `src/lib/bands.ts` にある
- バンド紹介に略称(BSJO、SAO、TNWJO)は出さない。正式名だけを書く
- 本文の文字は `ink` を使う。コントラスト比は `paper` 上で 12.4:1、`paper-light` 上で 14.3:1
- アイコンに近い `pink` と `blue` は、`paper` 上で 3.07:1 と 4.1:1 しかなく、文字に使うと WCAG AA の 4.5:1 に届かない。そのため文字用に暗くした `pink-deep`(`paper` 上で 4.76:1)と `blue-deep`(同 5.18:1)を用意した
- ボタンは `pink-deep` の背景に `paper-light` の文字にする
- ダークモードは作らない。`prefers-color-scheme` にも対応しない

## 3. 見た目の方針

- 見る人の大半はスマートフォンなので、390px 幅を基準に設計し、PC は広げた形として作る。押せる要素は高さ 44px 以上、本文は 16px 以上、補助の文字も 12px 以上にする。ヘッダーは画面上部に固定し、長いページのどこからでもメニューを開けるようにする
- 日本語は文節で折り返す(`word-break: auto-phrase`)。単語の途中で改行しない
- 手描きの部品(アイコンのロゴ、吹き出し、鍵盤、楽器を持った人物、キャラクター `public/images/swing_chara.png`)を、見出しやヒーローに部品として使う。部品は画像(SVG か透過 PNG)にして `public/images/hand/` に置く。CSS や SVG フィルターで手描き風の線を作らない
- アイコンの高解像度の元データは残っていない。400px 四方の画像から部品を切り出し、紙の色を透過させて使う。拡大して表示するとぼやけるので、ロゴは幅 480px 程度までで表示する
- 画像生成 AI に描き直させる方法は、元の線や文字の形が変わるため、元の絵として扱わない。使う場合は部に見せて了承を得てから差し替える
- フォントは、本文と見出しに Zen Maru Gothic、吹き出しや手書きの注記に Klee One を使う。どちらも Google Fonts から読み込む。Noto Sans JP と Inter は使わない
- セクションの見出しは、英字の大見出しに日本語の小さなラベルを添える(例: 「NEWS」と「お知らせ」)。英語表示のときはラベルを出さない
- ナビゲーションは英日を併記する(例: 「About」の下に「部について」)。英語表示のときは英語だけにする
- お知らせの日付は付箋の形で示す
- セクションの境目は、紙をちぎった縁(`public/images/hand/torn-edge.png` で切り抜く)か、鍵盤の帯で区切る。直線や細い罫線で区切らない
- 濃い帯(背景 `ink`、文字 `paper-light`)は、部の紹介など1ページに1か所までにする

### やめるもの

いまのサイトにある次のものは、作り直すときにすべて外す。`.claude/skills/swing-ui/SKILL.md` にも同じ内容を書いてある。

- 黒背景、ぼかした光の円(`blur-3xl`)、ノイズの重ね、グラデーションの区切り線
- `rounded-2xl` のカードを同じ大きさで並べるだけのレイアウト、カードの背景に大きく薄い番号を置く装飾
- `font-mono` と広い字間を組み合わせた英字の小見出し(「Our Bands」「Join Us」など)
- 音符のパーティクル(`src/components/home/MusicNoteParticles.tsx`)と Ken Burns(写真がゆっくり拡大する演出)
- `backdrop-blur` のすりガラス風ヘッダー
- 絵文字をアイコンの代わりに使うこと、感嘆符を多用する文言

### ヒーロー

- 左に手描きのロゴ(吹き出し「ALL YOU NEED is JAZZ」を含む)と紹介文とボタン、右に microCMS の `site.heroImages` のライブ写真を置く。写真は紙にマスキングテープで留めた形で少し傾け、角からキャラクターがのぞく。スマートフォンではロゴ、紹介文、ボタン、写真の順に縦に並ぶ
- 写真が複数あるときは6秒ごとに切り替える。切り替えは 700ms のクロスフェードだけにし、拡大などの動きは付けない(写真の入れ替えは急に変わると目障りなので、6 章の 300ms の上限の例外とする)
- 写真が1枚も登録されていないときは、`paper` の背景に手描きのロゴを大きく置く
- ヒーローの中に、見学・入部の案内(`/contact`)とスケジュール(`/schedule`)へのボタンを置く。新入生がスマートフォンで最初の画面から見学の方法にたどり着けるようにするため

## 6. 演出

ローディング画面とスクロール時のアニメーションは、作り直して残す。

- ローディング画面は、ブラウザのセッションで最初に開いたときだけ表示する。いまの `src/routes/__root.tsx` の `sessionStorage` による制御をそのまま使う
- 内容は、鍵盤の上をキャラクターが歩き、アイコンのロゴが描かれていくもの。長さは 1.5 秒以内にし、クリックかキー入力で飛ばせるようにする
- スクロール時のアニメーションは、見出しの下に色鉛筆の黄色のマーカー線(`public/images/hand/marker.webp`。アイコンの吹き出しの塗りから質感を取った画像)が左から引かれる程度にする。1回だけ再生し、上に戻っても逆再生しない。長さは 300ms 以内
- `prefers-reduced-motion: reduce` のときは、ローディング画面を出さず、スクロール時のアニメーションとヒーローの写真の切り替えを止める

## 7. microCMS

### プランと運用

- 無料の Hobby プランを使う。API は5個、メンバーは3人、API キーは1個まで。データ転送量が月 20GB を超えると、その月は API が止まる
- メンバーが3人までなので、広報担当用の共有アカウントを1つ作り、担当が代わるときにパスワードを引き継ぐ。引き継ぎの手順を README に書く
- README に、記事の投稿とトップ画像の差し替えの手順を、プログラミングを知らない部員向けに書く

### API

| API | 形式 | フィールド |
|---|---|---|
| `posts` | リスト | `category`(セレクト「お知らせ / ライブレポート」、必須)、`title`(必須)、`eventDate`(日付、必須)、`eyecatch`(画像)、`body`(リッチエディタ、必須)、`bands`(3バンドの正式名の複数選択)、`title_en`、`body_en` |
| `site` | オブジェクト | `heroImages`(複数画像、最大5枚)、`heroCopy`、`heroCopy_en`、`email`、`instagram`、`x` |
| `bands` | リスト | `band`(3バンドの正式名から1つ選ぶ、必須)、`desc`(必須)、`desc_en`、`photo`、`instagram`、`x`、`order`(並び順、必須) |
| `history` | リスト | `year`、`text`、`text_en` |

- セレクトの選択肢は、部員が読んで分かる日本語と正式名にする。コードの側(`src/server/cms.ts`)で識別子に直す。選択肢の文言を変えるときは、コードも同時に変える
- お知らせとライブレポートを `posts` にまとめ、API を1個空けておく。Google カレンダーの予定を microCMS で管理したくなったときなどに使う
- 英語のフィールドは任意。空のときは日本語を表示する
- スキーマは `docs/microcms-schema/` に JSON で置き、管理画面からインポートできるようにする

### 取得と表示

- API キーはサーバー側だけで使う。TanStack Start の `createServerFn` から `microcms-js-sdk` を呼び、ブラウザには渡さない
- 環境変数は `MICROCMS_SERVICE_DOMAIN` と `MICROCMS_API_KEY`。ローカルでは `.env.local`、本番では Vercel の環境変数に置く
- ページは SSR で表示し、レスポンスに `Cache-Control: s-maxage=60, stale-while-revalidate=600` を付ける。記事を公開してから1分ほどでサイトに反映されるので、Webhook と再ビルドは使わない
- 画像は microCMS の画像 API の URL に `?w=<表示幅>&fm=webp` を付けて縮小する
- 環境変数がないときや API が失敗したときも、ページは表示する。お知らせとライブレポートは「まだありません」と空であることを示す。バンド紹介と歴史は、確認済みの内容を `src/lib/defaults.ts` に持たせ、microCMS が空のあいだはそれを表示する
- 存在しない記事の URL は 404 を返す

## 8. 範囲外

- Google カレンダー API の組み込み
- OB・OG 向けページ(`/for-obog`)
- ライブレポートへのアメブロの埋め込み
- 記事の英語訳を必須にすること

## 9. 完了の条件

- `npx impeccable detect http://localhost:3000/<パス>` を全ページに実行し、検出が0件になる。0件はデザインが良いことの証明ではないので、1440px と 375px のスクリーンショットでも確認する
- 本文の文字のコントラスト比が 4.5:1 以上
- 375px と 390px の幅で横スクロールが出ず、押せる要素がすべて高さ 44px 以上ある(本文中のリンクを除く)
- microCMS の環境変数がない状態で `npm run build` と `npm run preview` が成功し、各ページが空の状態で表示される
- microCMS で公開した記事が、1分ほどで `/news` か `/live-reports` に表示される。`site.heroImages` を差し替えると、トップのヒーローに反映される
- OS の「視差効果を減らす」を有効にすると、ローディング画面とアニメーションが止まる
- サイト上の日本語の文言が no-ai-smell の `references/writing-ja.md` に沿っている
